## 2026-08-24｜注册上下文复用与风控收敛（TechChangeSpec-2026-08-24-Registration-Context-Reuse）

### 方案总览与实现要点

本批次把 GCash 提链输入从“仅 AT”扩展为注册上下文 JSONL。服务端和前端均支持 `access_token`、`session_token`、`device_id`、`account_id`、`browser_profile`、`proxy_ref`、`registered_at` 等字段。任务创建时对用户本次提供的代理池计算与注册项目相同的 SHA-256 前 16 位引用，优先选择原注册节点；上下文包和公开 API 均不保存或返回原始代理凭据。

`GCashChain` 默认配置调整为 `chrome136`，构造时复用注册设备 ID 和 NextAuth Session Cookie。Cookie 同时进入 `curl_cffi` 会话与 Playwright 临时前端上下文，确保 Bootstrap 不再是未登录状态。同一账号的外层重试继续使用原 Session、设备和浏览器配置。

建单内部遇到 `unusual activity` 时仍在同一会话生成一次 `chatgpt_checkout` Sentinel 并重试；第二次仍失败时不再触发外层换代理重试。代理预检、连接超时等网络类问题仍可轮换节点，但账号风险上下文保持固定。

公开任务结果增加风险上下文布尔标记和脱敏尝试诊断，包括卡点、错误、匿名节点引用和重试原因。前端失败卡片展示这些信息。新增任务列表接口并使用 `sessionStorage` 恢复最近任务，避免页面刷新后丢失任务 ID。

### 问题回溯与根因分析

原项目只接收 AT，导致注册阶段的 Session、`oai-did`、账号上下文和代理亲和全部丢失。`GCashChain` 每次构造都会生成新设备 ID，外层重试又重新构造链路并轮换代理，刚注册账号在数分钟内出现多次设备和出口变化。

Playwright 前端上下文的 Cookie 白名单原先排除了 `__Secure-next-auth.session-token`，因此用于采集观察头和部署上下文的浏览器实际处于未登录 Bootstrap；后续协议请求却携带 AT 和账号 ID，形成前后状态不一致。

`_create_checkout()` 已在原会话内为异常活动生成 Sentinel 并重试一次，但 `_retry_decision()` 又把相同错误判定为可外层重试，最多继续轮换五个节点。该行为会放大失败请求，并使真实卡点难以判定。

此前任务只保存在内存，页面刷新后没有任务列表入口；失败结果只显示最终错误，内部 `attempt_history` 又包含原始代理，既不适合直接公开，也不利于安全复盘。

### 行为变更明细

1. 普通 AT 文本和原结构化输入保持兼容。
2. JSONL 中账号 ID 与 AT 声明的账号 ID 不一致时拒绝该行。
3. 有 `proxy_ref` 且本次代理池匹配成功时使用原注册节点；匹配失败时产生警告并使用备用节点。
4. Session Token 只保存在进程内任务和隔离 Cookie 容器中，不进入公开任务响应。
5. `attempt_history` 内部也不再保存原始代理，改存匿名 `proxy_ref`。
6. 公开错误会替换 AT、Session、账号 ID、代理和 JWT 形态内容。
7. `GET /api/jobs` 返回当前进程保留期内的脱敏任务列表。
8. `unusual activity` 二次失败后停在 `create_checkout`，`attempts_used` 为 1，不再跨节点放大请求。

### 风险与回滚策略

Session Token 与 AT 同等敏感，任务进程暴露或操作者保存 JSONL 都会产生账号风险。服务仍缺少登录层，默认只监听本机；部署到其他环境时需由维护方配置访问控制。

代理引用只在代理字符串完全一致时匹配；动态会话型代理若 SID 不同会回退到备用节点并显示警告。回滚时可移除上下文字段与亲和匹配，恢复仅 AT 模式，但会重新引入设备、Session 和出口漂移。

Playwright Chromium 与 `curl_cffi` 是不同网络实现，即使 UA 和配置统一为 Chrome 136，也仍存在实现层差异。真实上游规则和优惠资格随时可能变化，模拟测试只能验证本项目控制流。
