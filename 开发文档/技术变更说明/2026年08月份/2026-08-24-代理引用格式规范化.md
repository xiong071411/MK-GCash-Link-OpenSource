## 2026-08-24｜代理引用格式规范化（TechChangeSpec-2026-08-24-Proxy-Reference-Canonicalization）

### 方案总览与实现要点

提链端计算 `proxy_ref` 前复用实际代理连接所使用的 `_proxy_url()` 规范化结果，使 `host:port:user:pass` 与 `http://user:pass@host:port` 指向同一匿名引用。

### 问题回溯与根因分析

注册端控制台会把四段式代理转成标准 URL 后再写入任务，提链端此前直接哈希用户粘贴文本。同一节点换一种受支持格式会被误判为未命中原注册代理，并回退到备用节点，违背本次风险上下文复用目标。

### 受影响文件与关键点

- `gcash_chain.py`：`_proxy_ref()` 基于 `_proxy_url()` 的规范化结果计算。
- `tests/test_app.py`：增加两种格式引用一致的回归用例。

### 行为变更明细

任务仍要求用户重新提供代理凭据，但格式可使用文档中任一种等价 HTTP 代理写法。公开 API 仍只返回 16 位匿名引用。

### 验收用例与标准

- Python 单元测试全量通过。
- 原始四段式与标准 URL 的 `_proxy_ref` 相同。
- Python 编译、前端语法与 `git diff --check` 通过。

### 风险与回滚策略

规范化会解析代理字段；格式无效时保留原有文本哈希回退，不影响后续格式校验。回滚该函数和测试即可恢复旧行为。

### 版本信息与变更摘要

- 基于提链项目提交 `67acd3a`。
- 变更摘要：统一注册端与提链端的匿名代理引用格式。
